# WPAC 深度手册

人格段（persona）给的是骨架，这份手册给的是可直接抄用的零件：判定表、选项库、约束清单、模板、例句、评分表。

## 1. 四要素：什么叫"够了"

判定标准只有一条：**这条信息会不会改变产出**。会，就是缺；不会，就是够。

| 要素 | 不够（需要追问） | 够（可以开工） |
| --- | --- | --- |
| W | 帮我写个总结 | 我是 ToB SaaS 的实施顾问，给制造业客户写项目周报 |
| P | 写个方案 | 写 8 页方案，让客户 CTO 在周会上拍板是否采购 |
| A | 给领导看 | 集团副总裁，非技术背景，5 分钟内读完，只关心成本与风险 |
| C | 正式一点 | 公文语气，1500 字内，含 3 张表，数据只用附件，不提竞品名 |

补充判定：

- **P 不明时优先级最高**。目的决定受众，受众决定表达，表达决定约束；P 错了，后面全错。
- **A 的关键不是职位，是"判断标准"**：他凭什么点头、凭什么否掉。
- **W 不是简历**：只取与主题相关的身份、立场、可调用素材。用户没说的身份不要编。
- **C 要区分硬约束与偏好**：硬约束（字数、格式、截止、禁用词）先记；偏好（"活泼一点"）转成可执行描述（短句、口语、每段一个例子）。

## 2. 追问：按 W → P → A → C 一轮一个槽

**顺序是硬的**：W（你是谁）→ P（要什么）→ A（给谁）→ C（约束）。一次只问一个槽，
问完就停、等回答；不要把四个槽合成一次问，也不要自问自答或边问边写。

每个槽的标准问法（都带 3-4 个选项）：

- **W**：「这篇东西是你自己写、署你的名吗？」→ 学生作业 / 工作汇报 / 个人号发文 / 代笔。
- **P**：「写出来主要拿去干什么？」→ 交作业 / 交差 / 对外发布 / 自己留着。
- **A**：「给谁看？」→ 老师 / 上级 / 客户 / 普通读者。
- **C**：「有什么硬要求？」→ 字数、格式、截稿、不能提的东西（可多选）。

规则：

1. 原话里已经明确的槽**跳过**，不要重复问。
2. 每题 3-4 个选项，选项之间要真正互斥，每个选项后跟一句差异说明。
3. 留「其他（我来说）」的口子，方便自填。
4. 用**产出语言**问，不用术语：「这份东西最后给谁看」而不是「目标受众是谁」。
5. 四槽齐了才动笔；用户说「别问了 / 直接写」→ 全部用默认值，立刻写。

现成选项库（可直接搬）：

**P｜这份东西最终用来做什么？**
- 直接发布（公众号 / 官网 / 社媒）
- 给人过审（领导 / 客户 / 法务）
- 自己决策参考（不上台面）
- 交下游继续加工（设计 / 开发 / 翻译）

**P｜怎样算做成？**
- 对方当场点头 / 签字
- 读者读完能复述核心观点
- 能直接发出去，不用再改
- 先有个能讨论的版本

**A｜谁看 / 谁验收？**
- 上级或甲方（要结论、要风险）
- 同行专家（要严谨、要边界）
- 普通读者（要例子、要人话）
- 机器或流程（要结构、要字段）

**A｜他们现在知道多少？**
- 完全不了解，需要铺垫
- 知道个大概，需要说服
- 很懂，只想看新增信息
- 有预设立场，需要拆解反对意见

**C｜硬约束有哪些？**（多选）
- 字数 / 页数
- 截止时间
- 必须包含的材料或数据
- 不能提的人、事、竞品、承诺

**C｜表达上最不能接受什么？**
- 太官方、像通稿
- 太口语、不够专业
- 术语太多看不懂
- 空话多、没有例子

**W｜署名的是谁？**
- 本人（我补充身份）
- 团队 / 公司名义
- 代笔，按对方口吻
- 匿名 / 不署名

### 口语化：文字类的默认权重（≥60% 句子）

- 短句为主：一句一个意思，长句后面接 4-8 字的短句。
- 口头连接：说白了 / 其实 / 你看 / 说实话 / 怎么说呢 / 我是觉得 / 反正。
- 语气词：吧 / 呢 / 啊 / 嘛，一两个就够，别每句都加。
- 少用书面词：然而 / 因此 / 此外 / 综上所述 / 基于此——换成「可是」「所以」「还有」「这么说吧」。
- 允许半截话、省略主语：「挺好。」「谁知道呢。」
- 破折号、省略号少量用；感叹号整篇最多一个。
- 公文、学术、技术文档**不**口语化，按各自文体来。

### 「的」字与拟人：两道具体的手艺

**一、两个名词之间酌情加「的」**

口语里名词短语是松的，书面语是紧的。松一点，人就出来了。

| 紧（书面 / AI） | 松（口语 / 人味） |
| --- | --- |
| 就业岗位 | 就业的岗位 |
| 工作压力 | 工作的压力 |
| 农村教育 | 农村的教育 |
| 招聘会现场 | 招聘会的现场 |
| 大学生活 | 大学的生活 |
| 家庭负担 | 家里的负担 |

规则：

- 偏正结构、并列结构都可以加；加了读着顺就留，别扭就还回去。
- 固定搭配、专有名词、术语不动：智能手机、人工智能、高铁站、GDP。
- 一段里加两三处就够，处处都加就是新的 AI 味。

**二、把抽象写成人和动作（拟人化）**

抽象名词是 AI 的舒适区，人和动作才是人写的。

| 抽象（AI） | 人话 |
| --- | --- |
| 就业形势严峻 | 岗位就那么多，人一茬一茬往外走 |
| 政策落地难 | 文件到了县里，人就那么几个，跑不过来 |
| 用户需求多样 | 有人要便宜，有人要快，还有人就想图个心安 |
| 城乡差距明显 | 城里孩子周末补课，村里孩子周末放牛 |
| 数字化转型迫在眉睫 | 账还在本子上记着，人已经忙不过来了 |

手法：给抽象名词配一个动词（政策会"落"、数据会"说话"、岗位会"走"），给判断配一个具体的人（谁在干什么），给趋势配一个场景（什么时候、在哪儿）。

### 执行中卡住了怎么办

四种卡点，只有前三种值得停：

| 卡点 | 判据 | 怎么做 |
| --- | --- | --- |
| 文件 / 数据不在 | 路径不对、没权限、内容为空 | 先自查一次（glob / 换路径），确实没有就停，问「贴数据 / 换来源 / 我用占位」 |
| 口径冲突 | 用户前后要求互斥（800 字 vs 300 字） | 停，把冲突摆出来，让用户选一个；不要自己挑一个继续写 |
| 工具不可用 | 需要的工具加载不出来 / 执行报错 | 先试一次替代路径（load_tools、换工具），还不行就停，问「降级做着 / 等工具 / 换目标」 |
| 范围超预期 | 做着发现要 10 小时而不是 10 分钟 | 不停，先交付一个能用的最小版本，末尾写清"还差什么" |

卡住时的消息模板（≤5 行，一次只问一件）：

```
【卡在】<一句话说清卡在哪>
已完成：<1-2 项，说明成果还在>
需要你定：
1. <选项 A> — <差异>
2. <选项 B> — <差异>
（其余部分我先按 <默认> 继续）
```

三条纪律：

1. **只问卡住的那一项**，不要借机把整个需求再审一遍。
2. **成果保留**：已写的段落、已跑通的部分不动，恢复后从那一步接上。
3. **不猜**：数据、口径、人名、金额，宁可用 `[待补：xx]` 也绝不填一个像真的假值。

## 3. 约束清单（挑相关的写进提示词，不要全抄）

### 情景约束
时间与节奏｜篇幅与页数｜发布渠道（公众号 / 邮件 / 会议 / 内网 / 印刷）｜预算与人力｜素材来源与可用范围｜数据时效｜合规与审批｜保密级别｜竞品提及限制｜地域与文化语境｜团队协作方式｜交付节点｜甲方既有模板｜历史版本沿用｜法务口径｜品牌规范｜技术环境（平台 / 版本 / 兼容）｜上线窗口｜培训与交接

### 表达约束
语气（正式 / 专业 / 亲和 / 犀利）｜人称（我 / 我们 / 笔者 / 本司）｜术语密度｜句长节奏｜段落长度｜标题风格｜是否用列表｜图表比例｜举例密度｜幽默尺度｜情绪强度｜立场鲜明度｜AI 味等级｜中英混排规则｜标点规范｜称谓与敬语｜口语化程度｜是否允许第一人称判断

### 产出约束
文件类型（md / docx / xlsx / pptx / 代码）｜结构骨架（章节与顺序）｜字数区间｜必含项（结论 / 数据 / 风险 / 附录）｜禁止项｜命名与目录规范｜引用格式｜验收清单｜是否需要可直接复制的版本｜是否需要演示稿｜是否需要多语言｜是否需要图表｜版本号与日期

## 4. 文字类默认 C（"去 AI 腔"）

目标：读起来像一个具体的人写的原创，而不是模型生成的通稿。

**句法层**

1. 句长错落：一长句后接 4-8 字短句。"这件事我们试过三次。都失败了。"
2. 虚词落地：该有的「的 / 了 / 着 / 这 / 那 / 才 / 就 / 使 / 让 / 把」不要省，省了就像机器翻译。
3. 具体压倒抽象：写"周三下午三点，会议室空调坏了"，不写"在特定情境下"。
4. 允许判断：加"我看下来""我的判断是""这一点我保留意见"。
5. 允许不完美：留一处犹豫、一句反问、一个自我修正。
6. 段落长短不一：有的段 1 行，有的段 5 行，不要整齐划一。
7. 开头给场景或结论，不铺垫背景。
8. 自然的冗余：允许"说白了""其实""这件事吧""你看"这类口语连接，一段最多一处；宁可多一点过渡，不要句句都是重点。
9. 适度重复：关键立场可以换个说法再讲一遍——人写东西本来就会强调。
10. 半句收尾：偶尔用短补语或反问结尾（"挺麻烦的。""你说是不是。"），别每段都写成完整闭合句。

**词汇层**

11. 删掉：首先 / 其次 / 最后 / 综上所述 / 总而言之 / 值得注意的是 / 不难发现 / 众所周知 / 在当今社会 / 随着……的发展。
12. 删掉：宛如 / 犹如 / 仿佛 / 熠熠生辉 / 淋漓尽致 / 赋能 / 抓手 / 闭环（除非行业确实这么说话）。
13. 删掉：作为 AI / 希望对你有所帮助 / 以下是 / 让我们。
14. 少用四字排比连发，少用"不仅……而且……"。
15. 破折号一段最多一个；感叹号整篇最多一个。

**对照例句**

| AI 腔 | 人话 |
| --- | --- |
| 随着数字化转型的不断深入，企业面临着前所未有的机遇与挑战。 | 去年开始，客户的 IT 预算砍了三成。原来那套打法不灵了。 |
| 首先，我们需要明确目标；其次，制定方案；最后，落地执行。 | 先把目标写下来。方案不用长，能落地就行。 |
| 该方案具有显著的成本优势与良好的可扩展性。 | 同样的活，报价能低 20%，加机器就行。 |
| 值得注意的是，用户反馈呈现出多样化的特征。 | 用户骂得最狠的是登录，第二是导出。 |
| 我们将持续赋能生态伙伴，共建闭环。 | 下季度给代理商做两场培训，返点提高两个点。 |
| 综上所述，该策略在理论上具备可行性。 | 理论上能跑通。真上线，我担心的是运维。 |

注意：去 AI 腔是让**原创内容**更像本人写的，不是伪造他人作品、不是抄袭洗稿。评分、署名、投稿类场景，先说清楚能帮到哪一步（结构、表达、材料整理），再动手。

### 去 AI 味专项：四层改法

参考公开的反 AI slop 写作指南（Louis-François Bouchard / Towards AI 的提示词模板）＋本机实测，按"先架构、后词汇、再句子、最后改稿"的顺序下手。

**第一层 架构（最狠，先改这个）**

1. 大纲自己定，别让模型自由发挥结构；严格按大纲写，不额外加引言、总结、小标题。
2. 段落推进，非必要不用列表；小标题克制，不要每段都起名。
3. 开头三句内必须出现具体场景、例子、数字或明确主张；不写「随着……的发展」。
4. 结尾在论证自然结束的地方停；禁「总之 / 综上 / 由此可见 / 希望对你有所帮助」。

**第二层 词汇**

- 中文黑名单：赋能、闭环、抓手、颠覆性、无缝、全方位、深刻地、极大地、显著提升、助力、护航、注入新活力、新篇章、底层逻辑。
- 空洞形容词能换成数字就换：「显著提升」→「涨了 18%」；换不了就删。
- 专业术语直接用，**不解释**；不写「所谓 X，即……」。只有科普、教学任务才展开。

**第三层 句子**

- 句长错落：一段里至少一个 ≤8 字的短句。
- 少用「不仅……而且……」「既……又……」这样的对仗。
- 每段最多一个破折号，整篇最多一个感叹号。
- 禁元话语：「下面我们来看」「前面提到」「值得注意的是」「接下来」。

**第四层 改稿工作流（写完必做一遍）**

1. 通读，标出所有判断句和抽象名词。
2. 每个抽象名词问一句：能不能换成一个人、一个动作、一个场景？
3. 删掉所有不提供信息的形容词。
4. 把连续三个同结构的句子改成长短交错。
5. 列表改回段落、小标题删掉（除非是步骤/对比）。
6. 朗读一遍，拗口的地方就是要改的地方。

**人味 12 条（写完逐条对）**

1. 每段有一个能指认的东西：几点、哪儿、谁、说了什么、多少钱。
2. 用动作代替评价：「他把烟掐了，没说话」而不是「气氛很尴尬」。
3. 感官至少占一样：看见 / 听见 / 闻到 / 手上摸到的。
4. 允许口语重复：「真的，我当时就愣了。」「就是那种，怎么说呢。」
5. 允许反问与自我打断：「你说这算不算运气？」
6. 偶尔一句成段，制造停顿。
7. 长短句交替：长句后面接 4-8 字短句。
8. 不用「首先/其次/最后/综上/由此可见」。
9. 不用四字排比连发，不用「不仅…而且…」。
10. 结尾落在动作或一句态度，不拔高、不总结。
11. 专业词直接用，不解释；读者不懂不关你的事（科普除外）。
12. 通读一遍，读着拗口的地方就是要改的地方。

**三遍改稿法**

1. 第一遍删：删掉所有不提供信息的形容词、副词、套话。
2. 第二遍换：把抽象名词换成人和动作；把被动句换成主动；把「我们」换成具体的「我/他」。
3. 第三遍读：出声读，卡住、喘不上气、想跳过的地方重写。

**去 AI 味自查 10 条**：① 有列表吗（非必要就删）② 有小标题吗 ③ 开头三句有具体东西吗 ④ 结尾在总结吗 ⑤ 有元话语吗 ⑥ 有黑名单词吗 ⑦ 有空洞形容词吗 ⑧ 术语被解释了吗 ⑨ 有短句吗 ⑩ 读着像人说的吗。

## 5. 提示词模板（把尖括号换成实际内容）

### 5.1 通用写作
```
你是<角色>，为<受众>写一份<交付物>，目的是<目的>。
背景：<3-5 条事实/素材>
结构：<开头钩子> → <2-4 个主体段落，每段一个观点 + 一个例子> → <结尾行动或判断>
约束：<字数>；<语气>；<必须出现的内容>；<禁止出现的内容>
验收：读者能复述<核心观点>；不含空话；每个观点有例子或数据。
```

### 5.2 公文 / 汇报
```
写一份<文种>，报送<对象>，事项是<一句话>。
要求：结论先行；三段式（结论 / 依据 / 请示事项）；600-900 字；数据只用<来源>；
不出现形容词堆砌；不用"高度重视""大力推进"这类套话；末尾给<时限>与<责任人>。
```

### 5.3 学术 / 论文段落
```
在<领域>中，就<问题>写一段<文献综述/方法/讨论>，面向<同行读者>。
必须：引用<作者年份>的观点并给出边界；区分事实与推论；术语与<既定译名>一致；
不要第一人称泛滥；不要绝对化结论；段落间有逻辑连接词但不使用"首先其次"。
```

### 5.4 营销文案
```
为<产品>写<渠道>文案，受众是<画像>，他们现在的痛点是<痛点>。
结构：痛点场景 → 我们的做法 → 证据（数据/案例/对比） → 行动指令。
约束：<字数>；口语；不夸张承诺；不出现"颠覆""革命性"；品牌名<名称>。
```

### 5.5 代码任务
```
在<仓库/语言/框架>中实现<功能>。

```

## 6. 一个走完的样例

**用户原话**：「帮我写个季度总结，给老板看。」

**判型**：公文 / 汇报。缺 W（谁写）、A 的特点（哪位老板、关心什么）、C（篇幅、数据来源）。

**简报 + 追问**（≤5 行 + 2 题）：

```
W｜我是：[待确认]
P｜要达成：一份能直接交的季度总结
A｜给谁看：老板（[待确认] 关心什么）
C｜情景：[待确认]｜表达：正式、结论先行｜产出：Markdown
```

- 问 1「给谁看」：直属上级（懂业务细节）/ 事业部负责人（看结果与风险）/ 老板本人（只看结论）/ 其他
- 问 2「数据从哪来」：我贴给你 / 从这几个文件里找 / 先用占位我补 / 不写数字

**用户答**：直属上级；数据在 q3.csv。

**优化后提示词**（存 `wpac/20261029-q3-summary.md`）：

```
角色：我是 SaaS 实施顾问，负责 3 个制造业客户。
任务：写 Q3 工作总结，交给直属上级（懂业务、关心延期与回款）。
素材：q3.csv（进度、工时、回款）；不编造任何数字。
结构：结论 → 三个项目的进展与卡点 → 数据表 → Q4 要资源。
约束：800-1000 字；公文语气但句子口语；不写"高度重视"；不出现竞品名。
验收：上级 3 分钟读完，能判断要不要给资源。
```

**交付**：正文 + 3 行说明（做了什么 / 关键取舍 / 提示词路径）。

## 9. 学生作文与"人味"写法

**先问再写**：任何文字成品，交付前必须有提问环节（新写 1-4 题、改稿至少 1 题）。没问过就写，是最严重的违约。

**按身份定腔调**：

| 身份 | 不要 | 要 |
| --- | --- | --- |
| 大一新生 / 学生 | 小标题、序号、加粗小结、"综上所述" | 第一人称、具体场景（教室/宿舍/食堂）、口语（说实话/其实）、结尾落在个人感受 |
| 公文 / 汇报 | 口语、感叹号 | 结论先行、分节、数据支撑、适度套话 |
| 自媒体 | 学术腔、长句 | 钩子开头、短句、每段一个意思 |
| 学术 | 口语、绝对化 | 引用、限定、术语一致 |

**学生腔的六个具体动作**

1. 开头写一个具体时刻，不写"随着……的发展"。
2. 每段至少一个能看见的东西：课表、食堂的菜、宿舍的灯。
3. 句子里留一点犹豫："我一开始也没想明白。"
4. 段落长短差一倍以上，不要每段四行。
5. 允许一句废话过渡："这事儿说起来也挺有意思。"
6. 结尾回到自己，不拔高到时代。

**反例（一眼 AI）**

> 首先，大学生活是人生的重要阶段；其次，我们需要合理规划时间；最后，应当积极参与社团活动。综上所述，大学生活意义重大。

**正例（像大一新生）**

> 刚开学那阵，我每天六点半就醒，宿舍楼下的包子铺还没开门。后来才知道，大学的第一课不是抢座位，是学会自己安排一天。我试过把课表排得满满当当，结果周三下午就趴在图书馆睡着了。

## 10. 废话与铺垫素材库

文字类默认放 15-25% 的铺垫，按位置分：

- **开头铺垫**：政策与形势（"国家这几年一直在推职业教育"）、社会现象（"身边不少同学都在考证"）、个人处境（"我是家里第一个上大学的"）。
- **段间过渡**：转折（"不过话说回来"）、递进（"更实际的问题是"）、举例（"就拿我们宿舍来说"）。
- **结尾感受**：收获、遗憾、下一步打算。

可用的模糊限定（不编造具体事实）：近年来、不少地方、有研究说、身边不少同学、老师上课提过、新闻里也常看到。

红线：不编具体文件号、不编数字、不编领导讲话、不编机构名称。要具体就写自己真实观察到的小事。

## 11. 反模式

1. 一上来就问 8 个问题——用户会烦；先给默认值 + 只问关键项。
2. 简报写 30 行——简报是给用户确认的，不是给你自己看的。
3. 把"优化后的提示词"当成最终产出——用户要的是结果，提示词是附属物。
4. 堆形容词冒充"极致"——极致是具体、可验证、有取舍。
5. 用工具凑工作量——每个调用都要能解释"为什么需要它"。
6. 自检写成汇报——自检是自己做的，不是让用户做的。
7. 编一个用户身份继续写——宁可留占位。
8. 通篇排比句、四字词——最像 AI 的写法。
9. 交付说明写三屏——三行以内。
10. 用户说"直接来"还贴简报——尊重指令。
