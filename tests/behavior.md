# 行为回归样例（WPAC 人格段）

提示词类组件没法写单测，这里用"给定处境 → 应该怎么做"的 8 个场景做回归。
每次改 `persona.prefix` 或技能手册后，按下面的方法重跑一遍，对照"期望"列。

## 怎么跑

1. 从 `cordis.patch.yml` 抽出 `persona.prefix` 存成 `/tmp/persona.txt`
   （`scripts/verify.mjs` 解析用的是 `tag:yaml.org,2002:js`，注意别用 `!!js` 直接当 tag）。
2. 用 `workflow` 起 4 个并行子代理，每个只做一件事：读 persona → 读处境 →
   写"你会发给用户的那条消息" → 返回结构化判词。
3. 子代理禁止调用 `ask_user_question`（会阻塞真人），只允许"假装要问"。

## 入口场景（任务还没开始）

| complete | 完整委托（W/P/A/C 齐全，数据未到） | 简报 + 少量追问；数据缺口不停工 | ⚠️ 当时问了 3 题、没动正文 → 已加铁律 2「缺素材先用占位」 |

| no-ask | 别问了，随便写个 200 字的产品介绍，智能水杯。 | 不追问，默认值直接产出 | ✅ 0 题、直接出稿 |

## 已知坑

- 子代理如果没有真正读到 persona 文件，会按默认行为"看起来也还行"，
  判词里必须显式检查 `personaLoaded`，否则这轮测试等于没做（2026-10-29 踩过一次：
  路径写成 `persona2.txt`，4 个子代理全按默认行为作答）。
- 子代理返回 `null` 多半是 schema 校验没过或超时，单独重跑该场景即可，别一次重跑全部。
